# SemanticSearch

A document search system that combines semantic (vector-based) and keyword search. Documents are chunked, embedded locally with **AllMiniLmL6V2** (384-dimensional vectors), and stored in **Oracle Database 23c** using its native AI Vector Search extension. Built with **Spring Boot** on the backend and **Angular** on the frontend.

## Features

- Upload documents as PDF, TXT, MD, or plain text
- Three search modes: **semantic**, **keyword**, and **hybrid**
- Optional re-ranking with multi-signal scoring (recency, phrase match, metadata, chunk length)
- Result highlighting at sentence level
- Document management dashboard with statistics
- Fully local embedding model — no external API calls

## Setup

### 1. Start Oracle in Docker

```bash
docker run -d --name oracle-vector-db -p 1521:1521 -e ORACLE_PWD=password -v oracle_data:/opt/oracle/oradata container-registry.oracle.com/database/free:latest
```

### 2. Initialize the Database

Connect to the database as `sysdba`:

```bash
docker exec -it oracle-vector-db sqlplus sys/password@FREEPDB1 as sysdba
```

Then run the following SQL:

```sql
CREATE USER semantic_search IDENTIFIED BY semantic_search;
GRANT CONNECT, RESOURCE, DBA TO semantic_search;

CREATE TABLE semantic_search.documents (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    file_name VARCHAR2(300) NOT NULL,
    source_type VARCHAR2(30) DEFAULT 'manual' NOT NULL,
    uploaded_at TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
    pdf_title VARCHAR2(500),
    pdf_author VARCHAR2(300),
    file_size_bytes NUMBER,
    CONSTRAINT chk_documents_source_type
        CHECK (source_type IN ('pdf', 'txt', 'md', 'manual'))
);

CREATE TABLE semantic_search.document_chunks (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    document_id NUMBER NOT NULL,
    chunk_index NUMBER NOT NULL,
    page_number NUMBER,
    content CLOB NOT NULL,
    embedding VECTOR(384, FLOAT32),
    CONSTRAINT fk_document_chunks_document
        FOREIGN KEY (document_id)
            REFERENCES semantic_search.documents(id)
            ON DELETE CASCADE,
    CONSTRAINT uq_document_chunk_index UNIQUE (document_id, chunk_index)
);

CREATE INDEX semantic_search.idx_document_chunks_doc_id
   ON semantic_search.document_chunks(document_id);

CREATE INDEX semantic_search.idx_documents_uploaded_at
   ON semantic_search.documents(uploaded_at);
```

## How Search Works

1. The query is embedded using the same AllMiniLmL6V2 model used at index time.
2. **Semantic** — Oracle `VECTOR_DISTANCE(..., COSINE)` finds the closest chunk embeddings.
3. **Keyword** — `DBMS_LOB.INSTR` scans chunk content for substring matches.
4. **Hybrid** — merges both result sets, taking the max score per chunk.
5. If **re-ranking** is enabled, scores are further adjusted by:
   - Exact phrase presence
   - PDF title/author match
   - Recency of the document
   - Chunk length (penalty for very short or very long chunks)
   - Boost for documents with multiple matching chunks
6. Matching sentences in results are highlighted using sentence-level semantic scoring.
